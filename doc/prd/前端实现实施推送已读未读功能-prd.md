# 前端实现实施推送已读未读功能 PRD

## 1. 需求概述

### 1.1 需求名称

实施推送已读/未读功能

### 1.2 需求目标

在系统顶部导航栏右侧工具区，为 AI 助手入口增加未读角标能力。当前端发起异步业务后，后端任务完成时能够通过推送机制通知前端，前端实时更新未读数，并支持已读清零。

### 1.3 核心诉求

- 用户无需刷新页面即可看到后台异步任务结果是否返回。
- 未读数在多个标签页下保持尽量一致。
- 断线重连后可恢复订阅与未读数状态。
- 用户点击入口查看或执行“全部已读”后，未读角标清零。

## 2. 需求背景

目前页面在触发部分异步业务后，用户只能依赖 toast、页面刷新或等待外部通知感知结果。例如标题优化等业务已存在“结果请查看通知”的交互文案，但前端导航栏没有真实的未读提示能力，导致：

- 用户无法明确知道是否有新的处理结果返回。
- 异步任务完成后，用户需要主动刷新或反复进入相关页面查看。
- 多标签页场景下，未读状态无法同步。
- 前端没有统一的通知推送接入规范，后续新异步业务难以复用。

因此，本次需要补充“未读数初始化 + 推送更新 + 已读处理 + 顶部角标展示”的完整前端方案。

## 3. 用户价值

- 用户可实时感知异步任务完成状态。
- 减少无效刷新与重复进入业务页面的操作成本。
- 增强系统对异步业务结果的可见性。
- 为后续更多推送型业务提供统一接入基础能力。

## 4. 适用范围

### 4.1 本期包含

- 顶部导航栏右侧 AI 助手入口的未读角标展示。
- 未读数初始化接口调用。
- WebSocket/STOMP 推送接入。
- 未读数状态管理。
- 全部已读动作。
- 断线自动重连。
- 多标签页下的未读状态同步策略。

### 4.2 本期不包含

- 完整消息中心列表页。
- 通知筛选、搜索、分组、分页。
- 单条已读、单条删除。
- 浏览器系统通知、桌面通知。
- 消息详情页。

## 5. 角色与场景

### 5.1 用户角色

- 普通业务用户：关注自己发起或与自己相关的异步任务结果。
- 运营用户：需要在执行标题优化、导入、分析等后台任务后，通过统一入口查看结果提醒。

### 5.2 典型场景

- 用户提交一个后台异步处理任务。
- 后端任务完成后推送新的未读数。
- 用户停留在任意页面，顶部导航栏角标实时更新。
- 用户同时打开多个标签页，某一页收到推送后，其他页面也应同步角标。
- 用户点击入口查看消息或执行全部已读，角标清零。

## 6. 接入范围与页面位置

### 6.1 导航栏接入点

实际导航栏右侧工具区位于：

- `library/components/VabRightTools/index.vue`

本期未读能力的图标承载组件位于：

- `library/components/VabAiAssistant/index.vue`

说明：

- 本期角标展示在 `VabAiAssistant` 的 `vab-icon` 上。
- `VabRightTools` 是导航栏右侧统一挂载位置，PRD 中的“导航栏通知图标”应落在该区域，而不是散落到各业务页面。

### 6.2 后续可扩展方向

- 若后续产品改为独立“通知中心”图标，也应复用本期通知 store、推送连接和未读状态能力。
- 本期不要求重做 `VabNotice` 组件，但需避免和其未来能力冲突。

## 7. 功能目标

### 7.1 页面初始化目标

- 页面首次进入布局后，先拉取当前用户未读数。
- 然后建立推送连接。
- 当后端推送新未读数时，角标自动刷新。

### 7.2 展示目标

- 未读数大于 0 时，显示红色角标。
- 未读数等于 0 时，隐藏角标。
- 大于 99 时显示 `99+`。

### 7.3 已读目标

- 用户点击入口后，可以触发“全部已读”或预留面板中的已读动作。
- 已读成功后前端本地未读数立即归零。
- 推送后再次收到新消息时，角标重新显示。

## 8. 用户流程

1. 用户登录进入系统。
2. 全局布局初始化通知能力。
3. 前端请求未读数接口，获取当前 `unreadCount`。
4. 前端建立 WebSocket/STOMP 连接。
5. 前端订阅当前用户对应的通知队列。
6. 用户发起某个异步业务。
7. 后端业务完成后向用户队列推送最新未读数。
8. 前端收到消息并更新通知 store。
9. 顶部导航栏角标自动刷新。
10. 用户点击入口查看消息或触发全部已读。
11. 前端调用已读接口，成功后清空未读数。

## 9. 页面交互设计

### 9.1 图标展示

- 图标沿用 `library/components/VabAiAssistant/index.vue` 当前入口。
- 图标位置保持不变，不改动导航栏整体布局。
- 未读角标展示在图标右上角。

### 9.2 角标展示规则

- `0`：不展示角标。
- `1-99`：显示实际数字。
- `>=100`：显示 `99+`。

### 9.3 点击行为

本期允许以下两种实现方式，推荐第一种：

- 推荐方案：点击图标打开现有组件/弹窗，并在打开动作中触发全部已读。
- 兼容方案：若本期通知面板尚未建设完成，可点击图标后直接触发全部已读，后续再扩展详情面板。

约束：

- 无论采用哪种方式，已读动作必须可追踪、可联调。
- 若点击图标仅打开 AI 弹窗而不代表“消息已查看”，则不能自动标记全部已读，需要有显式已读动作。

说明：

- 该点需产品最终确认。本 PRD 默认采用“点击入口后触发全部已读”的最小闭环方案。

## 10. 状态设计

建议在 Pinia 中新增全局通知 store，例如：

- `src/store/modules/notification.ts`

### 10.1 核心状态

- `unreadCount`: 当前未读数
- `connected`: 当前连接状态
- `subscribed`: 当前是否已完成订阅
- `reconnectAttempts`: 当前重连次数
- `lastSyncTime`: 最近一次成功同步时间
- `socketClient`: WebSocket / STOMP 客户端实例

### 10.2 核心动作

- `initUnreadCount()`
- `connectSocket()`
- `subscribeUserQueue()`
- `disconnectSocket()`
- `handleNotificationMessage(payload)`
- `markAllRead()`
- `syncUnreadCount(count)`
- `resetState()`

## 11. 接口设计

### 11.1 初始化未读数接口

```http
GET /api/notifications/unread-count
```

返回示例：

```json
{
  "code": 200,
  "data": {
    "count": 5
  }
}
```

前端要求：

- 页面初始化时调用一次。
- 成功后将 `data.count` 写入 `notificationStore.unreadCount`。
- 失败时不阻塞页面渲染，默认按 `0` 处理，并保留重试能力。

### 11.2 全部已读接口

```http
POST /api/notifications/mark-read
```

请求说明：

- 本期按“全部已读”设计，不要求前端传单条消息 ID。

前端要求：

- 成功后立即将本地 `unreadCount` 置为 `0`。
- 若接口失败，则保留当前未读数并提示“已读失败，请稍后重试”。

## 12. 推送连接设计

### 12.1 技术方案

- 协议：WebSocket
- 客户端：`@stomp/stompjs`
- 连接地址：`/ws`
- 订阅地址：`/user/queue/notifications`

### 12.2 推送消息结构

建议消息体如下：

```json
{
  "userId": "user_123",
  "unreadCount": 5,
  "timestamp": "2026-03-23T12:00:00Z"
}
```

前端处理规则：

- 若 `payload.unreadCount` 为合法数字，则直接覆盖本地未读数。
- 若消息结构不合法，则忽略该条消息并记录日志。
- 不因为单条坏消息断开连接。

## 13. 初始化与销毁策略

### 13.1 初始化时机

推荐在全局布局层或导航栏右侧工具区初始化通知能力，避免多个页面重复建连。

建议位置：

- 布局组件
- `library/components/VabRightTools/index.vue` 的上层布局容器

推荐流程：

1. 用户登录后进入系统。
2. 调用 `initUnreadCount()`
3. 调用 `connectSocket()`
4. 连接成功后执行订阅

### 13.2 销毁时机

- 用户退出登录时主动断开连接。
- 账号切换时重置 store。
- 页面整体卸载时释放客户端实例。

## 14. 重连策略

- 首次连接失败时自动重试。
- 最大重试次数：5 次。
- 重试间隔：指数退避，例如 `1s / 2s / 4s / 8s / 16s`。
- 超过最大重试次数后停止自动重试。
- 停止自动重试后，不弹全局阻断错误；允许用户继续使用页面。

建议补充：

- 下一次用户刷新页面或重新登录时重新初始化连接。
- 可在控制台或调试日志中输出重连状态，便于排查。

## 15. 多标签页同步策略

本期要求“多个标签页角标尽量一致”，前端建议采用以下策略：

- 每个标签页都建立自己的推送连接，分别接收后端消息。
- 当某标签页调用“全部已读”成功后，通过 `localStorage` 或 `BroadcastChannel` 广播已读结果。
- 其他标签页收到广播后，同步将本地 `unreadCount` 置为 `0`。

建议广播字段：

```json
{
  "type": "notification-read-all",
  "timestamp": 1710000000000
}
```

说明：

- 若浏览器环境不支持 `BroadcastChannel`，可退化为 `storage` 事件。
- 本期不要求实现复杂的消息列表跨页同步，只要求角标数量同步。

## 16. 异常与兜底策略

### 16.1 未读数初始化失败

- 页面正常渲染。
- 默认角标按 `0` 处理。
- 后续如推送成功，仍可继续更新角标。

### 16.2 WebSocket 建连失败

- 不阻塞页面。
- 保留当前未读数。
- 自动进入重试流程。

### 16.3 订阅失败

- 视为连接未完成。
- 进入重连或重新订阅逻辑。

### 16.4 推送消息异常

- 忽略非法消息。
- 打印日志。
- 不影响连接存活。

### 16.5 已读接口失败

- 不要本地直接清零。
- 向用户提示失败信息。

### 16.6 后端推送链路中断

- 前端仍可通过刷新页面重新拉取未读数。
- 本期不强制引入定时轮询作为兜底。

## 17. 组件设计建议

### 17.1 `NotificationBadge.vue`

职责：

- 纯展示未读角标。
- 根据 `notificationStore.unreadCount` 显示或隐藏。
- 不承载 WebSocket 连接逻辑。

建议接入方式：

- 可直接内嵌在 `library/components/VabAiAssistant/index.vue`
- 也可作为该组件内部的小型子组件

### 17.2 `useNotificationSocket.ts`

职责：

- 封装 STOMP 客户端初始化
- 建连
- 订阅
- 重连
- 断开连接

### 17.3 `notificationStore`

职责：

- 存储全局未读状态
- 协调初始化接口与推送消息
- 对外提供已读动作
- 管理跨标签同步

## 18. 视觉与交互细则

- 角标需固定在图标右上角，不影响当前图标 hover 动效。
- 红色角标建议使用圆角胶囊样式，兼容 `99+`。
- 数字需要垂直居中。
- 当数字较小时也应有最小宽度，避免挤压。
- 不建议在每次收到推送时弹出 toast，避免高频打扰。
- 若后续业务要求高优先级提醒，再单独设计 toast 规则。

## 20. 验收标准

- 用户进入系统后，前端能够拉取当前未读数并正确展示。
- 未读数为 `0` 时不显示角标。
- 未读数为 `1-99` 时显示准确数字。
- 未读数大于等于 `100` 时显示 `99+`。
- 后端推送新未读数后，导航栏角标可在 1 到 2 秒内更新。
- 多标签页登录同一账号时，某页执行全部已读后，其他页角标同步清零。
- 断网恢复后，连接可自动重建并继续接收推送。
- 点击入口执行已读后，本地角标立即隐藏。
- 连接异常不会阻塞系统其他页面使用。

## 21. 人工验证步骤

1. 登录系统，进入任意页面。
2. 观察顶部导航栏右侧 AI 助手图标，确认初始角标与接口返回一致。
3. 模拟后端推送一条 `unreadCount=1` 的消息，确认角标显示 `1`。
4. 再推送 `unreadCount=8`，确认角标更新为 `8`。
5. 推送 `unreadCount=120`，确认角标显示 `99+`。
6. 点击入口执行全部已读，确认角标立即隐藏。
7. 打开第二个标签页登录同一账号，确认两个页面角标一致。
8. 在第一个标签页执行全部已读，确认第二个标签页也同步清零。
9. 模拟断网再恢复，确认连接可自动恢复并继续收到推送。
10. 模拟推送非法消息，确认页面不中断、控制台有日志。

## 22. 风险与注意事项

- 若推送消息不是“全量 unreadCount”而是“增量 +1/-1”，前端处理复杂度会明显上升。本 PRD默认后端推送全量未读数。
- 若点击 AI 助手图标既要承担 AI 能力入口，又要承担通知已读动作，产品需明确是否存在语义冲突。
- 若用户未打开任何系统页面，则前端无法实时接收推送，该场景不属于本期前端能力范畴。
- 若后端没有用户级队列隔离，前端无法保证消息只属于当前用户。

## 23. 待确认项

- 点击 `VabAiAssistant` 图标时，是否默认执行“全部已读”。
- 已读动作是点击图标即触发，还是打开弹层后点击“全部已读”按钮触发。
- 后端推送的是“全量未读数”还是“增量事件”。
- 是否需要在通知角标外，再增加最近一条消息摘要展示。
- 后续是否要从 AI 助手图标迁移到独立通知图标。

## 24. 结论

本次需求不是单纯增加一个红点，而是建立一套完整的通知未读能力，包括：

- 全局未读状态管理
- 初始化接口同步
- WebSocket/STOMP 推送更新
- 已读清零动作
- 多标签页同步
- 顶部导航栏统一展示

该方案落地后，可先服务于“异步任务完成结果提醒”，后续再扩展为完整消息通知中心。
