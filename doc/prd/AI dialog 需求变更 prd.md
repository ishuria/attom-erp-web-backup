# AI dialog 未读消息需求变更 PRD

## 需求背景

当前 AI 对话侧边栏仅展示会话标题和创建时间，无法明确提示某个会话存在多少条未读消息。原始方案仅考虑未读红点，但这无法表达后端返回的实际未读次数，也不利于用户快速判断优先查看的会话。

本次需求调整为：

- AI 会话列表按会话维度展示未读数量。
- 未读提示使用数字角标，不使用单纯红点。
- 用户进入对应会话后，需要触发未读数量减少逻辑，并同步更新前端显示。

## 需求目标

- 在 AI 会话侧边栏清晰展示每个会话的未读数量。
- 当未读数量大于 0 时，用户能在会话卡片右上角看到数字角标。
- 当用户切换到某个有未读的会话时，前端调用后端接口减少该会话未读数，并同步更新当前会话角标。

## 展示需求

### 1. 展示位置

- 未读数量展示在 AI 会话侧边栏的单个会话卡片上。
- 角标位于会话卡片右上角区域。
- 视觉上需要更靠右，并相对顶部略向下偏移，避免与卡片圆角和右侧操作按钮完全重叠。

### 2. 展示样式

- 角标为红底白字数字徽标。
- 当未读数量为 0 或空时，不展示角标。
- 当未读数量为 1 到 99 时，显示实际数字。
- 当未读数量大于 99 时，统一显示为 `99+`。

### 3. 数据来源

- 未读数量由会话列表接口返回。
- 前端需兼容后端可能返回的字段命名，例如：
  `unreadCount`
  `unreadNum`
  `noReadCount`
- 前端内部统一收敛为 `unreadCount` 字段进行渲染。

## 接口对接

### 1. 会话列表接口

- 用途：获取 AI 会话列表及每个会话的未读数量。
- 现有接口：`GET /ai/conversations/list`
- 要求：后端在会话列表项中返回未读数量字段。

示例返回字段：

```json
{
  "id": 1001,
  "title": "商品标题优化",
  "createdAt": "2026-04-02 10:20:30",
  "unreadCount": 3
}
```

### 2. 未读数量减少接口

- Method：`POST`
- URL：`/ai/conversations/{conversationId}/unread-count/decrease`
- Desc：AI 会话减少未读消息数量
- Path 参数：`conversationId`，会话 id
- Response：返回 `Boolean`

说明：

- 该接口用于在用户查看会话时，通知后端减少该会话未读数量。
- 本期按现有接口能力接入，不扩展额外请求体。

## 交互逻辑

### 1. 会话列表初始化

- 页面初始化或刷新会话列表时，前端读取每个会话的未读数量。
- 若某会话 `unreadCount > 0`，则在该会话卡片右上角显示数字角标。

### 2. 切换会话时的处理

- 当用户点击切换某个会话时，若该会话未读数量大于 0，则需要调用：
  `POST /ai/conversations/{conversationId}/unread-count/decrease`
- 调用成功后，前端需要同步更新当前会话的未读数量显示。

### 3. 前端同步规则

- 若接口调用成功：
  前端将该会话的 `unreadCount` 按后端约定进行减少。
- 若当前后端接口仅返回 `Boolean`，前端本期按保守策略处理：
  将当前进入会话的 `unreadCount` 直接更新为 `0`。
- 若后端后续返回新的剩余未读数，则前端再切换为以后端返回值为准。

### 4. 异常处理

- 若减少未读数量接口调用失败：
  当前会话仍可正常切换和查看消息。
- 失败时不阻断页面主流程。
- 前端保留当前未读角标，不做错误清零，避免错误覆盖实际未读状态。

## 非需求范围

- 本期不处理消息气泡级别的未读红点展示。
- 本期不新增全局未读汇总角标。
- 本期不调整 AI 消息详情区的消息排序和加载逻辑。
- 本期不设计复杂的逐条消息已读回执能力。

## 验收标准

- 会话列表接口返回未读数量时，前端能正确显示数字角标。
- 未读数量为 0 或空时，不显示角标。
- 未读数量大于 99 时，前端显示 `99+`。
- 角标展示在会话卡片右上角，且不会明显遮挡标题或操作按钮。
- 点击存在未读数量的会话时，会调用减少未读数量接口。
- 减少未读数量接口失败时，不影响用户进入会话。
- 减少未读数量接口成功后，当前会话未读数量会在页面上同步减少或清零。

## 备注

- 若后端后续明确“减少未读数量”的具体规则，例如每次进入会话减少 1 条，或进入即全部清零，需要以前后端联调结果为准。
- 当前前端推荐优先支持“进入会话后清零”的展示策略，因为接口返回仅为 `Boolean`，无法可靠推断剩余未读数。
